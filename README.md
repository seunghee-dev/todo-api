# todo-api

회원가입과 로그인을 하고, 로그인한 사용자가 **자기 할 일만** 추가·조회·완료 처리·삭제할 수 있는 REST API 서버입니다.
로그인하면 JWT(로그인 토큰)를 받고, 이후 요청마다 이 토큰으로 사용자를 확인합니다.
화면 없이 JSON으로만 주고받습니다.

## 기술 스택

`pom.xml` 기준입니다.

| 항목 | 내용 | 버전 |
|---|---|---|
| 언어 | Java | 21 |
| 프레임워크 | Spring Boot (`spring-boot-starter-parent`) | 4.1.2 |
| 웹 | `spring-boot-starter-webmvc` | Spring Boot 관리 버전 |
| DB 접근 | `spring-boot-starter-data-jpa` (JPA) | Spring Boot 관리 버전 |
| 입력값 검증 | `spring-boot-starter-validation` | Spring Boot 관리 버전 |
| 비밀번호 암호화 | `spring-security-crypto` (BCrypt만 사용, Spring Security 전체는 쓰지 않음) | Spring Boot 관리 버전 |
| 로그인 토큰 | `jjwt-api`, `jjwt-impl`, `jjwt-jackson` | 0.13.0 |
| DB | H2 (메모리 DB) + `spring-boot-h2console` | Spring Boot 관리 버전 |
| 테스트 | `spring-boot-starter-webmvc-test` | Spring Boot 관리 버전 |
| 빌드 | Maven Wrapper (`mvnw.cmd`) | |

## 액터
- 비로그인 사용자
- 로그인한 사용자

## 유스케이스 목록
1. 회원가입: 비로그인 사용자가 이메일과 비밀번호로 가입한다. (`POST /users`)
2. 로그인: 사용자가 로그인하고 토큰을 받는다. (`POST /auth/login`)
3. 할 일 추가: 로그인한 사용자가 할 일을 추가한다. (`POST /todos`)
4. 할 일 목록 조회: 로그인한 사용자가 내 할 일만 본다. (`GET /todos`)
5. 할 일 완료/삭제: 로그인한 사용자가 내 할 일을 완료(또는 미완료) 처리하거나 삭제한다. (`PATCH /todos/{id}`, `DELETE /todos/{id}`)

## 실행 방법 (Windows PowerShell)

### 1. 준비
- **Java 21**이 필요합니다. (`java -version`으로 확인)
- Maven은 따로 설치하지 않아도 됩니다. 프로젝트에 들어 있는 `mvnw.cmd`를 씁니다.

### 2. JWT_SECRET 환경 변수 설정
토큰 서명용 비밀키는 코드나 설정 파일에 적지 않고 환경 변수 `JWT_SECRET`에서만 읽습니다.
기본값이 없으므로 **설정하지 않으면 서버가 시작되지 않습니다.** 32바이트 이상이어야 합니다.

아래 명령은 48바이트 난수를 만들어 Base64 문자열로 바꾼 뒤 환경 변수에 넣습니다.

```powershell
$bytes = New-Object byte[] 48
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:JWT_SECRET = [Convert]::ToBase64String($bytes)
```

- 환경 변수는 설정한 PowerShell 창에서만 유효합니다. 서버도 같은 창에서 실행하세요.
- `$env:`로 설정한 값은 **지금 연 PowerShell 창에서만** 유지됩니다. 창을 새로 열면 다시 설정해야 합니다.
- 만들어진 키 값은 README, 코드, 커밋 어디에도 적지 마세요.
- 키를 바꾸면 이전에 발급한 토큰은 모두 쓸 수 없게 됩니다.

### 3. 서버 실행
```powershell
.\mvnw.cmd spring-boot:run
```
- 기본 주소: `http://localhost:8080`
- 동작 확인: `GET http://localhost:8080/health` → `{"status":"ok"}`
- H2 웹 콘솔: `http://localhost:8080/h2-console` (JDBC URL `jdbc:h2:mem:tododb`, 사용자 `sa`, 비밀번호 없음)

> **주의: 메모리 DB(H2)를 씁니다.** 서버를 끄거나 재시작하면 회원과 할 일 데이터가 모두 사라집니다.
> 서버 시작 시 테이블도 새로 만듭니다(`ddl-auto=create`). 재시작 전에 받은 토큰은 서명이 맞더라도
> 그 사용자가 DB에 없으므로 401을 받습니다. 다시 가입하고 로그인하세요.

### 4. 테스트 실행
```powershell
.\mvnw.cmd test
```
테스트는 `src/test/resources/config/application.properties`의 테스트 전용 가짜 키를 쓰므로 `JWT_SECRET` 없이도 실행됩니다.

## API 목록

오류 응답은 모두 같은 JSON 모양입니다: `{"status":401,"error":"Unauthorized","message":"..."}`

| 주소 | 방식 | 토큰 | 성공 응답 | 주요 실패 응답 |
|---|---|---|---|---|
| `/health` | GET | 불필요 | `200` `{"status":"ok"}` | - |
| `/users` | POST | 불필요 | `201` `{"id","email","createdAt"}` | `400` 본문 검증 실패, 비밀번호 72바이트 초과 / `409` 이미 가입된 이메일 |
| `/auth/login` | POST | 불필요 | `200` `{"accessToken","tokenType":"Bearer","expiresIn":3600}` | `400` 이메일·비밀번호가 비어 있음 / `401` 이메일 또는 비밀번호가 틀림 |
| `/todos` | POST | 필요 | `201` `{"id","title","completed":false,"createdAt"}` | `400` 제목 없음·200자 초과·본문 형식 오류 / `401` |
| `/todos` | GET | 필요 | `200` 내 할 일 배열(최신순), 없으면 `[]` | `401` |
| `/todos/{id}` | PATCH | 필요 | `200` 바뀐 할 일 `{"id","title","completed","createdAt"}` | `400` id가 숫자가 아님·본문 비었음·`completed` 없음 / `401` / `404` 없거나 남의 할 일 |
| `/todos/{id}` | DELETE | 필요 | `204` (본문 없음) | `400` id가 숫자가 아님 / `401` / `404` 없거나 남의 할 일 |

- `401`은 토큰이 없거나, 위조·만료됐거나, 토큰의 사용자가 DB에 없을 때 모두 같은 응답입니다. (`"로그인이 필요합니다."`)
- 없는 주소(`404`)와 허용하지 않는 방식(`405`)도 같은 JSON 모양으로 돌려줍니다. 단, 없는 주소도 열린 주소가 아니므로 토큰 없이 요청하면 `401`을 받습니다.

## 상세 명세: UC-1 회원가입
- 액터: 비로그인 사용자
- 요청: `POST /users` + 본문 `{"email":"a@test.com","password":"password123"}`
- 기본 흐름:
  1. 사용자가 이메일과 비밀번호를 보낸다.
  2. 시스템이 이메일을 정규화(앞뒤 공백 제거, 소문자)한다. `A@Test.com`과 `a@test.com`은 같은 계정이다.
  3. 시스템이 비밀번호를 BCrypt 해시로 바꿔 저장한다. 원문은 저장하지 않는다.
- 응답: `201` + `{"id":1,"email":"a@test.com","createdAt":"..."}` (비밀번호는 응답에 없음)
- 예외 흐름:
  - 이메일이 비었거나 형식이 틀렸거나 100자를 넘으면 400
  - 비밀번호가 비었거나 8자 미만·64자 초과면 400
  - 비밀번호가 UTF-8로 72바이트를 넘으면 400 `"비밀번호가 너무 깁니다."` (한글은 글자당 3바이트라 64자 이하여도 걸릴 수 있다)
  - 이미 가입된 이메일이면 409 `"이미 가입된 이메일입니다."`

## 상세 명세: UC-2 로그인
- 액터: 비로그인 사용자
- 사전조건: 가입된 계정이 있다.
- 요청: `POST /auth/login` + 본문 `{"email":"a@test.com","password":"password123"}`
- 기본 흐름:
  1. 사용자가 이메일과 비밀번호를 보낸다.
  2. 시스템이 계정을 확인한다.
  3. 시스템이 토큰을 발급한다.
- 응답: `200` + `{"accessToken":"eyJ...","tokenType":"Bearer","expiresIn":3600}`
- 예외 흐름:
  - 이메일이 없거나 비밀번호가 틀리면 401 오류를 반환한다. (`"이메일 또는 비밀번호가 올바르지 않습니다."`)
  - 필수 값이 비어 있으면 400 오류를 반환한다.
  - 빈 값 외의 형식·길이 검사는 하지 않고 모두 같은 401로 처리한다.
- 사후조건: 사용자는 토큰으로 다른 기능을 사용할 수 있다.

## 상세 명세: UC-3 할 일 추가
- 액터: 로그인한 사용자
- 요청: `POST /todos` + 본문 `{"title":"우유 사기"}` (헤더에 로그인 토큰 필요)
- 응답: `201` + `{"id":1,"title":"우유 사기","completed":false,"createdAt":"..."}`
- 예외 흐름:
  - 토큰이 없거나 잘못됐거나, 토큰의 사용자가 DB에 없으면 401
  - 제목이 비었거나 200자를 넘거나, 본문 JSON 형식이 틀리면 400
- 규칙: 본문에 `"userId"`를 넣어 보내도 무시한다. 누구의 할 일인지는 오직 토큰으로 정한다.

## 상세 명세: UC-4 할 일 목록 조회
- 액터: 로그인한 사용자
- 요청: `GET /todos` (헤더에 로그인 토큰 필요)
- 기본 흐름:
  1. 사용자가 토큰과 함께 목록을 요청한다.
  2. 시스템이 토큰의 사용자 것만 최신순(만든 시각 내림차순, 같으면 id 내림차순)으로 돌려준다.
- 응답: `200` + 배열 `[{"id":1,"title":"우유 사기","completed":false,"createdAt":"..."}]`
  - 할 일이 없으면 `200` + `[]`
- 예외 흐름:
  - 토큰이 없거나 잘못됐거나, 토큰의 사용자가 DB에 없으면 401 오류를 반환한다.
- 규칙: 누구의 목록인지는 오직 토큰으로 정한다. `?userId=` 같은 값은 무시한다.

## 상세 명세: UC-5 할 일 완료/미완료 변경, 삭제
- 액터: 로그인한 사용자
- 요청:
  - 완료/미완료 변경: `PATCH /todos/{id}` + 본문 `{"completed": true}` 또는 `{"completed": false}`
  - 삭제: `DELETE /todos/{id}` (완전 삭제)
- 응답:
  - 변경 성공: `200` + 바뀐 할 일 `{"id":1,"title":"우유 사기","completed":true,"createdAt":"..."}`
  - 삭제 성공: `204` (본문 없음)
- 예외 흐름 (위에서부터 먼저 검사):
  1. 토큰이 없거나 잘못됐으면 401 (인터셉터)
  2. `{id}`가 숫자가 아니거나(`/todos/abc`), 본문이 비었거나 `completed`가 빠지면 400
  3. 토큰은 유효하지만 토큰의 사용자가 DB에 없으면 401
  4. 없는 할 일이거나 남의 할 일이면 404 `"할 일을 찾을 수 없습니다."` (둘은 응답이 완전히 같다)
- 규칙: 사용자는 오직 토큰으로 정한다. 할 일은 `id`와 토큰의 사용자 id를 함께 조건으로 찾는다(`WHERE id = ? AND user_id = ?`).

## 인증 방식

- **JWT**: 로그인에 성공하면 HS256으로 서명한 토큰을 발급합니다. 토큰에는 사용자 id(`sub`), 발급 시각(`iat`), 만료 시각(`exp`)만 담고 이메일 같은 개인정보는 넣지 않습니다.
- **토큰 유효 시간은 1시간**입니다. 만료되면 다시 로그인합니다.
- 토큰이 필요한 주소에는 헤더에 다음을 붙입니다.
  - `Authorization: Bearer <로그인 응답의 accessToken>`
- **인터셉터(`AuthInterceptor`)**: 컨트롤러가 실행되기 전에 헤더의 토큰을 검사하고, 통과하면 토큰에서 꺼낸 사용자 id를 요청 속성(`userId`)에 담아 컨트롤러로 넘깁니다.
- 적용 범위(`WebConfig`): **기본은 모든 주소를 검사**하고, 아래 4개만 토큰 없이 열어 둡니다. 새 주소를 만들고 등록을 깜빡해도 자동으로 잠겨 있습니다.

  | 열린 주소 | 용도 |
  |---|---|
  | `/health` | 서버 상태 확인 |
  | `/users` | 회원가입 (정확히 `/users`만 열림, `/users/xxx`는 검사 대상) |
  | `/auth/login` | 로그인 |
  | `/error` | Spring 내부 오류 처리 주소 |

  `/h2-console`은 Spring 컨트롤러가 아닌 별도 서블릿이라 인터셉터를 거치지 않습니다.
- 토큰이 없거나, 위조됐거나, 만료됐으면 모두 같은 401 응답을 받습니다. 실패 이유를 구분해 알려 주지 않습니다.
  - `{"status":401, "error":"Unauthorized", "message":"로그인이 필요합니다."}`

## 설계에서 신경 쓴 점

1. **로그인 실패는 모두 같은 401**
   없는 이메일이든 틀린 비밀번호든 같은 메시지(`"이메일 또는 비밀번호가 올바르지 않습니다."`)로 응답합니다. 어느 쪽이 틀렸는지 알려 주면 가입된 이메일 목록을 알아낼 수 있기 때문입니다. 로그인 요청은 빈 값만 400으로 거르고, 형식·길이 검사도 하지 않습니다.
2. **가짜 해시로 응답 시간 맞추기**
   없는 이메일일 때 BCrypt 비교를 건너뛰면 응답이 눈에 띄게 빨라져, 시간만 재도 가입 여부를 알 수 있습니다. 그래서 서버 시작 시 같은 encoder로 가짜 해시를 하나 만들어 두고, 어떤 경우든 BCrypt 비교를 정확히 한 번 합니다.
3. **BCrypt 72바이트 검사**
   BCrypt는 비밀번호 앞 72바이트까지만 씁니다. 가입할 때는 72바이트를 넘으면 400으로 거절하고, 로그인할 때는 72바이트를 넘는 비밀번호를 실패(401)로 처리해, 앞 72바이트만 맞으면 뒤에 아무 글자나 붙여도 통과되는 일을 막습니다.
4. **사용자 id는 토큰에서만 받기**
   요청 본문 DTO에 사용자 id 필드를 두지 않고, `?userId=` 같은 쿼리 값도 읽지 않습니다. 컨트롤러는 인터셉터가 토큰에서 꺼낸 값(`@RequestAttribute`)만 씁니다.
5. **남의 할 일도 같은 404**
   할 일을 id로 꺼낸 뒤 주인을 비교하지 않고, 처음부터 `id`와 `user_id`를 함께 조건으로 조회합니다. 없는 할 일과 남의 할 일이 같은 빈 결과가 되므로 코드에서 구별할 수 없고, 응답도 같은 404입니다. 남의 할 일에 403을 주면 "그 id는 존재한다"는 정보가 새어 나가기 때문입니다.

## 확장 과제 (현재 구현되지 않은 부분)

- **회원가입 이메일 중복 응답(409)으로 가입 여부 노출**: 로그인은 가입 여부를 숨기지만, 회원가입에 가입된 이메일을 보내면 409를 받으므로 가입 여부를 알 수 있습니다. 요청 횟수 제한이나 이메일 인증(가입 여부와 상관없이 같은 응답 후 메일로 안내)으로 보완할 수 있습니다.
- **로그인 횟수 제한**: 지금은 비밀번호를 몇 번 틀려도 제한이 없어 대입 공격에 약합니다. IP나 계정 단위로 시도 횟수를 제한해야 합니다.
- **회원 탈퇴 시 기존 토큰 처리**: 탈퇴 기능이 아직 없습니다. 만들 경우, 이미 발급된 토큰은 만료 전까지 서명이 유효합니다. 현재 할 일 API는 매번 DB에서 사용자를 확인해 없으면 401을 주지만, 새 API를 만들 때도 같은 확인이 빠지지 않게 하거나 토큰 무효화 방법이 필요합니다.
- **본문 검증이 사용자 확인보다 먼저 실행되는 순서**: `@Valid` 본문 검증은 컨트롤러 진입 시점에, 사용자 존재 확인은 서비스에서 실행됩니다. 그래서 토큰은 유효하지만 사용자가 DB에 없을 때 본문이 잘못됐으면 401이 아니라 400이 나옵니다. 사용자 확인을 인터셉터 단계로 옮기는 방법을 검토할 수 있습니다.
- **H2를 MySQL로 바꾸기, H2 Console 끄기**: 지금은 메모리 DB라 재시작하면 데이터가 사라집니다. 배포할 때는 MySQL 같은 디스크 DB로 바꾸고 `ddl-auto=create`도 바꿔야 합니다. `spring.h2.console.enabled=true`인 H2 Console은 인터셉터를 거치지 않으므로 배포 때 반드시 꺼야 합니다.
- **로그아웃과 토큰 갱신**: 로그아웃 API가 없고, JWT는 서버에 저장하지 않으므로 만료 전에 무효화할 방법이 없습니다. 1시간이 지나면 다시 로그인해야 하므로, 리프레시 토큰으로 갱신하는 방식도 검토할 수 있습니다.
